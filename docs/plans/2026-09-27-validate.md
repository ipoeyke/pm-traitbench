# Stage 7 Validate Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use minipowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add stage 7, `validate`: check every stage 6 session against the ledger, a parameter-name grep, a leakage judge and a forbidden-trait judge; regenerate failing sessions through stage 6's session driver with the failure reasons as narrator feedback; drop sessions still failing at the attempt cap; write a hidden `validation` table and rewrite `sessions` and `dialogue_logs` in place.

**Architecture:** A new package `pm_traitbench.dialogue.validate` with one module per layer (`ledger.py`, `grep.py`, `judge.py`), a per-session attempt loop (`loop.py`) and the stage (`stage.py`). Judge calls and regeneration go through the existing `CachedClient` and `narrate_session`; the only stage 6 surface driven is the `feedback` argument. Layer functions are pure and take row models; only `loop.py` and `judge.py` are async.

**Tech Stack:** Python 3.13, pydantic v2 row models, numpy-free, `anthropic` SDK behind `LlmClient`, pytest with pytest-xdist, ruff.

Spec: `docs/specs/2026-09-27-validate-design.md`.

## Global Constraints

- Every config leaf carries `json_schema_extra={"basis": ..., "note": ...}` with `basis` in `sourced`, `design`, `guess`; `Config.dump_with_basis` raises otherwise.
- Every row model is a pydantic `BaseModel` with `ConfigDict(frozen=True, extra="forbid")`; every closed set of values is a `StrEnum` in `pm_traitbench/enums.py`, never a bare string.
- No table is read or written except through `DataStore` and a `TableSpec` in `tables/specs.py`. Every non-key column of `validation` is listed in `HIDDEN_COLUMNS`.
- Every LLM request goes through `CachedClient.send` with `scope=session_id`; a reply is `commit`ted only after it parses. No request carries `thinking` or a sampling parameter; bodies hold only `model`, `max_tokens`, `system`, `messages`, `output_config`.
- The judges never receive a trait id, bias param, trait value, stance line, signal mode, or the PM's persona row: only transcript text and, for the forbidden judge, the session's rendered avoid lines.
- The validator never parses prose for trades; ledger consistency reads `mentions` only.
- A validate run writes all three tables or none; a budget error wins over any other failure, as in stage 6.
- Code comments and docstrings never cite the plan or the spec; a non-obvious constant carries its domain reason inline.
- Plain dash, never an em dash, in any text including YAML and docs. No filler intensifiers.
- Commit messages: one Conventional Commits subject line, no body; keep the harness `Co-Authored-By` trailer only.
- Lint and format: `uv run ruff check <files>` and `uv run ruff format --check <files>` on touched files. Line length 100.
- Test command shape: `uv run pytest tests/<path> -v`; never a full-suite run inside a task step.

- Produces, `ledger.py`:
  - `check_trades(log: DialogueLog, skeleton: Skeleton, ledger: Sequence[LedgerRow], size_tolerance: float) -> tuple[str, ...]`: the failure reasons, empty when the layer passes. Rules, binding:
    - Only PM turns' mentions of `kind == TRADE` are considered.
    - A mention with `trade_idea_id is None` cannot exist (the `Mention` validator forbids it); no branch needed.
    - A mention matches a ledger row when `row.pm_id == skeleton.pm_id`, `row.trade_idea_id == mention.trade_idea_id`, `row.instrument_id == mention.instrument_id`, `row.tenor == mention.tenor`, `row.side == mention.side`, `row.date <= skeleton.date`, and `abs(mention.size - row.size) <= size_tolerance * row.size`.
    - A mention with no matching row yields the reason `trade not in ledger: {trade_idea_id} {instrument_id} {tenor or '-'} {side} {size}`.
    - Coverage: every ledger row with `row.date == skeleton.date` and `row.trade_idea_id in skeleton.trade_idea_ids` must be matched by at least one mention; each unmatched row yields `trade not mentioned: {trade_idea_id} {instrument_id} {tenor or '-'} {side} {size}`.
    - Reasons are sorted; a reason string appears once.
  - `count_level_warnings(log: DialogueLog, skeleton: Skeleton, lookup: MarketLookup, level_tolerance: float) -> int`: number of `kind == LEVEL` mentions that are not confirmed. Rules, binding:
    - Two values agree when `abs(a - b) <= level_tolerance * max(abs(b), 1e-9)`; `b` is the reference.
    - An advisor turn's level mention is confirmed when any number found by walking that same turn's `tool_calls[].result_json` (parsed JSON; recurse into dicts and lists; ignore `bool`; ignore rows with `is_error`) agrees with `mention.value`.
    - A PM turn's level mention is confirmed against the market on or before `skeleton.date`: `field == "price"` or `"spread_bp"` via `lookup.latest_price(instrument_id, date)` and that attribute; `field == "level"` with a tenor via `lookup.curve_on_or_before(instrument_id, date)[1][tenor]`; `field == "street_score"` or `"positioning_pct"` via `lookup.latest_consensus`; anything else, a missing row, a missing tenor, or a `None` attribute is unconfirmed.
