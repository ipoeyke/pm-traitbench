# Dialogue (Stage 6) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use minipowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add pipeline stage 6, `dialogue`: for every skeleton stage 5 wrote, generate one dated PM-copilot session with two `claude-opus-5-5` agents (a PM narrator and a simulated advisor that reads market data through tools), and write the public `sessions` table plus a hidden `dialogue_logs` table.

**Architecture:** A new `dialogue/` package. `client.py` is the single seam every model request passes through (`LlmClient` protocol, a disk-cached wrapper that doubles as the resume manifest, the Anthropic backend). `tools.py` answers advisor lookups from the stage 2 tables. `voices.py`, `turns.py` and `context.py` build a deterministic per-session context; `prompts.py` turns it into Messages API requests; `session.py` drives one session; `stage.py` runs all sessions concurrently and writes both tables or none.

**Tech Stack:** Python 3.13, pydantic v2, numpy, PyYAML, `anthropic` Python SDK (async client), asyncio, pytest (+ pytest-xdist), ruff; uv for everything.

## Global Constraints

- Source of truth: `docs/specs/2026-09-26-dialogue-design.md`. Read its "Decisions taken" and the section for your module before your task.
- Repo rule: no file under `src/` or `tests/` may mention `docs/`, a spec, a plan, task numbers or a coordinator. Docstrings and comments state the rule itself and its domain reason. Citing a published paper is allowed.
- Code style follows the surrounding code: frozen pydantic models with `extra="forbid"` for table rows and catalogue entries, frozen dataclasses for in-memory values, `StrEnum` for every closed set, full type hints, module docstring on every new module, line length 100, ruff rules `E, F, I, UP, B`. Inline comments 1-2 lines.
- Commands: tests `uv run pytest <path> -n auto -q`; lint `uv run ruff check <paths>` and `uv run ruff format --check <paths>`. CI runs `ruff check`, `ruff format --check`, `pytest`.
- Determinism: every random draw comes from `pm_traitbench.rng.stream(config.seed.root, "dialogue", pm_id, ...)`; never `random`, never an unseeded generator. Iterate dicts and sets in sorted order wherever order affects a draw or a request. Every request body is built deterministically, so the same inputs give the same cache key. A fully cached rerun writes byte-identical tables.
- Models: `claude-opus-5-5` for both agents. Never send `thinking` (adaptive is the model default and cannot be disabled), never send `temperature`/`top_p`/`top_k`, never force `tool_choice` `any` or `tool` (the model rejects them with a 400); only `{"type": "none"}` is used, at the tool-round cap. Effort goes in `output_config.effort`.
- Append-only histories: a message once sent in a session is never edited or removed; assistant responses are appended with their full `content` (thinking and tool blocks included) unchanged.
- Only valid responses are cached. A response is committed to the cache only after the caller validates it.
- Visibility: the advisor request never contains persona, rules, ideas, ledger, traits or skeleton text; the narrator request never contains a trait id, bias param name, trait value, signal mode or the word "bias". Tool calls and results never appear in `sessions`.
- Dependency direction: `dialogue/` may import `tables`, `enums`, `config`, `catalogues`, `errors`, `rng`, `stages`. Nothing outside `dialogue/` imports it except `pipeline.py` and tests. `dialogue/` never imports `engine`, `signals`, `gates` or `market` internals (it reads the market tables through `DataStore`).
- All-or-nothing: the stage writes both tables or neither.
- Living doc is `README.md` (no `ARCHITECTURE.md`); `docs/pm-dataset-plan.md` is also updated. Each doc change lands in the task that makes the old text wrong.
- Shared test fixtures live in `tests/dialogue/conftest.py` (created in Task 4, extended in Tasks 5 and 7). Consume them; never copy them.

```python
class LlmClient(Protocol):
    async def send(self, request: Mapping[str, Any]) -> dict[str, Any]: ...


def request_key(request: Mapping[str, Any]) -> str:
    """sha256 hex of the request serialised with sorted keys and no whitespace."""
    body = json.dumps(request, sort_keys=True, separators=(",", ":"), ensure_ascii=False)
    return hashlib.sha256(body.encode("utf-8")).hexdigest()


@dataclass(frozen=True)
class Reply:
    key: str
    response: dict[str, Any]
    cached: bool


@dataclass
class UsageTotals:
    calls: int = 0
    cache_hits: int = 0
    input_tokens: int = 0            # fresh calls only
    output_tokens: int = 0           # fresh calls only
    cache_read_tokens: int = 0       # fresh calls only


class CachedClient:
    def __init__(
        self,
        inner_factory: Callable[[], LlmClient],
        cache_dir: Path,
        token_budget: int | None,
    ) -> None: ...
    async def send(self, request: Mapping[str, Any]) -> Reply: ...
    def commit(self, reply: Reply) -> None: ...
    @property
    def totals(self) -> UsageTotals: ...


class AnthropicClient:
    def __init__(self, max_concurrency: int) -> None: ...
    async def send(self, request: Mapping[str, Any]) -> dict[str, Any]: ...
```

Behaviour:
- `CachedClient.send`: compute `request_key`; if `<cache_dir>/<key[:2]>/<key>.json` exists, return its stored response with `cached=True` and count a cache hit. Otherwise, if `token_budget` is set and fresh `input_tokens + output_tokens >= token_budget`, raise `DialogueBudgetError`; else build the inner client on first miss (`inner_factory()`, so a fully cached run never needs credentials), call it, add the response's `usage` to the fresh totals, and return `cached=False`. `calls` counts every `send`.
- `CachedClient.commit`: no-op for a cached reply; otherwise write `{"key", "model", "response"}` as JSON (sorted keys) to a temp file in the same directory and `os.replace` it into place. An uncommitted reply is never written, so the next `send` of the same request calls the inner client again.
- `AnthropicClient`: builds `anthropic.AsyncAnthropic()` lazily, sends `await client.messages.create(**request)` under an `asyncio.Semaphore(max_concurrency)`, returns `message.to_dict()`. Converts `anthropic.AuthenticationError`, `anthropic.PermissionDeniedError` and a client-construction failure into `DialogueError("no Anthropic credentials: run `ant auth login` or set ANTHROPIC_API_KEY")`; converts `anthropic.BadRequestError` into `DialogueError` with the API message; lets `RateLimitError`, `InternalServerError`, `APIConnectionError` and `APITimeoutError` propagate after the SDK's own retries (catch by typed class, never by message text). No request is sent to the network in tests.

```python
@dataclass(frozen=True)
class ToolOutcome:
    result: dict[str, Any]
    is_error: bool


@dataclass(frozen=True)
class MarketLookup:
    seed: str
    dates: tuple[date, ...]                     # the seed's trading days with a price row, sorted
    instruments: Mapping[str, Instrument]       # only instruments with rows on this seed
    # private indexes built in `build`

    @classmethod
    def build(
        cls,
        seed: str,
        instruments: Sequence[Instrument],
        prices: Sequence[Price],
        curves: Sequence[CurvePoint],
        consensus: Sequence[ConsensusRow],
        calendar: Sequence[CalendarEvent],
    ) -> "MarketLookup": ...

    def resolve(self, instrument: str) -> Instrument | None: ...   # exact id, else case-insensitive exact name


TOOL_DEFINITIONS: tuple[dict[str, Any], ...]   # five Messages API tool dicts, in AdvisorTool order


def run_tool(lookup: MarketLookup, name: str, tool_input: Mapping[str, Any], today: date) -> ToolOutcome: ...
```

Tool definitions: each has `name` (the `AdvisorTool` value), a one-sentence `description`, `strict: True`, and an `input_schema` with `additionalProperties: false` and every property `required`:
- `get_quote`: `{instrument: string}` -> `{instrument_id, name, date, price, spread_bp}` from the latest `market/prices` row on or before `today` (`spread_bp` null unless a credit issuer).
- `get_curve`: `{instrument: string}` for a sovereign curve or commodity -> `{instrument_id, name, date, levels: {tenor: level}}` from `market/curves` on the latest date on or before `today`, tenors in `Tenor` order.
- `get_consensus`: `{instrument: string}` -> `{instrument_id, name, date, street_score, street_view, positioning_pct, positioning}`.
- `get_calendar`: `{instrument: string, days_back: integer, days_forward: integer}` -> `{instrument_id, name, events: [{date, event, surprise}]}` covering the instrument's rows and market-wide rows (`instrument_id` null) within `days_back` trading days before and `days_forward` trading days after `today`. Rows dated after `today` carry `surprise: null` always, because a surprise is only known once the event happens; rows on or before `today` carry their stored surprise.
- `get_history`: `{instrument: string, n_days: integer}` -> `{instrument_id, name, field, points: [{date, value}]}` with the last `n_days` rows on or before `today`; `field` is `spread_bp` for a credit issuer and `price` otherwise.

Errors return `ToolOutcome(result={"error": <message>}, is_error=True)`, never raise: unknown `name`; unknown instrument (message lists up to 5 closest names from `difflib.get_close_matches` over the lookup's instrument names); `get_curve` on an instrument with no curve; no consensus rows for the instrument; `days_back` or `days_forward` outside `[0, 20]`; `n_days` outside `[1, 60]`; no row on or before `today`. Bounds keep a lookup to a desk's usual window and cap tool-result size. No lookup ever returns a row dated after `today` except calendar schedule rows as described.

Curve lookup: `curve_id` is the curve's `instrument_id` for `sovereign_curve` and `commodity` instruments; confirm against `market/curves` rows written by the market stage before relying on it, and fail the build with `DialogueError` if a curve's id matches no instrument.

Algorithm (binding):
1. Draw `n_turns` uniformly from `ranges.for_kind(skeleton.kind)`.
2. `n_reaction` = number of stances with `entry == StanceEntry.REVEALED_REACTION`. Raise `DialogueError` naming the session if `n_reaction > 1`, if `n_reaction == 1` and `skeleton.advisor_violation` is null, or if `n_reaction == 0` and it is set.
3. Minimum PM turns = `max(len(stances), 2 if n_reaction else 1)`; if `n_turns // 2` is below it, set `n_turns = 2 * minimum`. If that exceeds 8, raise `DialogueError` naming the session.
4. PM turn indices are 0-based. The reaction stance takes an index drawn uniformly from `1 .. n_pm - 1`; `violation_advisor_index` = that index minus 1 (the advisor reply just before it). 5. PM turn 0 gets `opening = OPENING_BY_KIND[skeleton.kind]` and `trades = tuple(day_trades)`; every other turn gets `opening=None`, `trades=()`. The opening frames the session; a stance on turn 0 is still delivered.

Flow (binding):
- Two append-only histories. Narrator: `[{"role": "user", "content": NARRATOR_OPENING_MESSAGE}]`. Advisor: empty.
- For PM turn `i` in `0 .. n_pm - 1`:
  1. Narrator: append `{"role": "system", "content": narrator_directive(ctx, i)}`; send `narrator_request(...)`; accept when `parse_turn` returns a value; append `{"role": "assistant", "content": response["content"]}`.
  2. Advisor: append `{"role": "user", "content": pm_text}`; if `i == violation_advisor_index`, append `{"role": "system", "content": skeleton.advisor_violation}` and mark this advisor turn `scripted_violation=True`, `directive=` the violation line. Then loop: send `advisor_request(...)`; if `stop_reason == "tool_use"` and every `tool_use` block names an `AdvisorTool`, accept, append the assistant content, run every tool with `run_tool(ctx.lookup, name, input, ctx.skeleton.date)`, append one `{"role": "user", "content": [tool_result blocks]}` (each `{"type": "tool_result", "tool_use_id", "content": json.dumps(result, sort_keys=True), "is_error"}`), and continue; after `config.max_tool_rounds` accepted tool rounds send once more with `tools_disabled=True` and record the warning `f"{session_id}: advisor reply {k} hit the tool-round cap"`. Accept a final reply when `parse_turn` returns a value; append its content; then append `{"role": "user", "content": final_text}` to the narrator history for the next PM turn (skip after the last advisor reply).
- Every accepted reply is `client.commit`-ed. A rejected reply (refusal, `max_tokens`, unknown tool name, unparsable or schema-invalid output) is not committed and the same request is re-sent; after `1 + config.max_retries` rejected attempts for one request, raise `DialogueError(f"session {session_id}: {reason}")`.
- `TurnLog.usage` sums `response["usage"]` over the accepted replies of the turn (cached replays carry the usage they were recorded with, so logs are identical across reruns). `request_hashes` lists the accepted replies' keys in order. `model` is the request's model.
- `Session` and `DialogueLog` copy `session_id`, `pm_id`, `date`, `kind`, `trade_idea_ids` from the skeleton; `voice_id` from `ctx.voice`. PM `TurnLog.directive` is the stance line if the turn had a stance, else the opening line on turn 0, else null.
