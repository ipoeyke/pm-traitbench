# Stage 8 Gate 2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use minipowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add stage 8, `gate2`: one full-context recovery call per PM that names which traits the PM shows and cites the sessions that show them, scored against ground truth and pooled into per-param exact-test verdicts that block the pipeline; plus report-only per-session bias-versus-preference classification of stated signals and a cross-PM 5-gram containment measure.

**Architecture:** A new package `pm_traitbench.gates.gate2` with pure text rendering (`transcript.py`, `overlap.py`), one request-parse-score module per model task (`recover.py`, `classify.py`), a pure aggregation module with the two exact tests (`aggregate.py`) and the stage (`stage.py`). Model calls go through the existing `CachedClient`, `send_until_accepted` and `base_request`; two shared dialogue helpers are generalised so a PM-scoped unit is labelled `pm`, not `session`. Four public tables; verdict hook raises `Gate2Error` after the tables are on disk, as Gate 1 does.

**Tech Stack:** Python 3.13, pydantic v2 row models, numpy, scipy (`scipy.stats.hypergeom`), `anthropic` SDK behind `LlmClient`, pytest with pytest-xdist, ruff.

Spec: `docs/specs/2026-09-28-gate2-design.md`.

## Global Constraints

- Every config leaf carries `json_schema_extra={"basis": ..., "note": ...}` with `basis` in `sourced`, `design`, `guess`; `Config.dump_with_basis` raises otherwise.
- Every row model is a pydantic `BaseModel` with `ConfigDict(frozen=True, extra="forbid")`; every closed set of values is a `StrEnum` in `pm_traitbench/enums.py`, never a bare string.
- No table is read or written except through `DataStore` and a `TableSpec` in `tables/specs.py`. The four Gate 2 tables are public: nothing is added to `HIDDEN_COLUMNS`.
- Every LLM request goes through `CachedClient.send` with `scope` = the PM id (recovery) or the session id (classification); a reply is committed only after it parses. Request bodies hold only `model`, `max_tokens`, `system`, `messages`, `output_config`; never `thinking` or a sampling parameter.
- The recovery request carries the bias param names, their definition lines, the candidate preference params with their catalogue values, the mandate and the PM-scope rule texts; never a trait id, a trait value, a stance line, a signal mode or which sessions carry signals. The classification request carries no trait vocabulary at all: no bias param name, no catalogue value list.
- A gate2 run writes all four tables or none; a `DialogueBudgetError` wins over any other failure. The verdict raises only after tables and run metadata are written.
- Nothing in `gates/gate2` imports from `dialogue.validate`, `signals` or `engine`; it reads tables and reuses `dialogue.client`, `dialogue.prompts.base_request`, `dialogue.stage` helpers and `catalogues`.
- Code comments and docstrings never cite the plan or the spec; a non-obvious constant carries its domain reason inline.
- Plain dash, never an em dash, in any text including YAML and docs. No filler intensifiers.
- Commit messages: one Conventional Commits subject line, no body; keep the harness `Co-Authored-By` trailer only.
- Lint and format: `uv run ruff check <files>` and `uv run ruff format --check <files>` on touched files. Line length 100.
- Test command shape: `uv run pytest tests/<path> -v`; never a full-suite run inside a task step.

### Task 5: Recovery request, parser, ground truth and scorer

**Files:**
- Create: `src/pm_traitbench/gates/gate2/recover.py`
- Modify: `tests/gates/gate2/fixtures.py` (extend)
- Test: `tests/gates/gate2/test_recover.py`

**Interfaces:**
- Consumes: `base_request` (`dialogue.prompts`), `CachedClient`, `last_text_json`, `send_until_accepted` (`dialogue.client`), `BiasDefinitions`, `PreferenceEntry`, `Catalogue.preferences_for` (`catalogues.models`), `Gate2Config`, `BIAS_PARAMS`, `Gate2Error`, row models from Task 1.
- Produces, `recover.py`:
  - `RECOVERY_SCHEMA: dict` exactly the spec's JSON schema, with `"title": "gate2_recovery"` at the top level (the fixtures route requests by schema title, as `tests/dialogue/validate/fixtures.py::_schema_title` does).
  - `@dataclass(frozen=True) class TraitTruth`: `kind: Kind`, `trait_id: str | None`, `truth_active: bool | None`, `truth_value: str | None`.
  - `compute_truth(traits: Sequence[Trait], drift_events: Sequence[DriftEvent], last_date: date, entries: Sequence[PreferenceEntry]) -> dict[str, TraitTruth]`: one entry per bias param from `traits` (kind bias; a PM must have all eight, else `Gate2Error`) and one per `entries` param.
