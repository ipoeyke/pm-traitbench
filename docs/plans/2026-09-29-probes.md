# Stage 9 Probes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use minipowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add stage 9, `probes`: per PM, per checkpoint of the PM's own schedule, write questions with deterministic ground truth of five types (trait presence, trait MCQ with an open twin, in-situ response, routine question, governance) into one `probes` table, calling no model.

**Architecture:** A new package `pm_traitbench.probes` with pure modules for checkpoints, context and supporting signals, closed-form MCQ actions and option assembly, market situations, and one builder per probe type, driven by `probes/stage.py`. Two Gate 2 helpers (truth at a date, validated-corpus check) move to package-root modules both stages share. One authored bank, `catalogues/probes.yaml`, holds every line of question text.

**Tech Stack:** Python 3.13, pydantic v2 row models, numpy, scipy (via existing `distributions`), pytest with pytest-xdist, ruff.

Spec: `docs/specs/2026-09-29-probes-design.md`.

## Global Constraints

- No model call anywhere in `probes/`. No import of `dialogue.client`, `anthropic` or any `CachedClient`.
- Every answer key is computed from `traits`, `drift_events`, `rules`, `signals`, the market tables and the engine's own decision functions; never from session text.
- Every random choice uses `rng.stream(config.seed.root, "probes", pm_id, day.isoformat(), purpose, *keys)`; nothing else draws randomness. A rerun on the same inputs writes a byte-identical `probes` table.
- Every config leaf carries `json_schema_extra={"basis": ..., "note": ...}` with `basis` in `sourced`, `design`, `guess`.
- Every row model is a pydantic `BaseModel` with `ConfigDict(frozen=True, extra="forbid")`; every closed set of values is a `StrEnum` in `pm_traitbench/enums.py`.
- No table is read or written except through `DataStore` and a `TableSpec`.
- `probes` hidden columns: `answer`, `source_a`, `source_b`, `source_c`, `source_d`, `supporting_signal_ids`. Hidden means never shown to a system under test.
- No line in `catalogues/probes.yaml` and no generated question contains a `BANNED_STANCE_WORDS` entry, a bias param name, or an em dash: a question that names the trait leaks the label the corpus hides.
- Dependency direction: `probes` may import `engine`, `catalogues`, `tables`, `traits_truth`, `corpus_checks`, `gates.gate2.transcript`, `signals.inputs`, `rng`, `config`. Nothing outside `probes` imports `probes` except `pipeline.py`. `catalogues` never imports `probes`.
- Multi-asset PMs have no sessions and get no probes.
- Code comments and docstrings never cite the plan or the spec; a non-obvious constant carries its domain reason inline.
- Plain dash, never an em dash, in any text including YAML and docs. No filler intensifiers.
- Commit messages: one Conventional Commits subject line, no body; keep the harness `Co-Authored-By` trailer only.
- Lint and format: `uv run ruff check <files>` and `uv run ruff format --check <files>` on touched files. Line length 100.
- Test command shape: `uv run pytest tests/<path> -v`; never a full-suite run inside a task step.

    1. `probe_id` starts with `f"p_{pm_id.replace('_', '')}_"`.
    2. Every `supporting_signal_ids` entry matches `_SIGNAL_ID_PATTERN`; the tuple is sorted and unique.
    3. Every non-null option is non-blank after strip.
    4. `form == OPEN`: all four options and all four sources null.
    5. `probe_type == TRAIT_PRESENCE`: `form == MCQ`, `option_a == "yes"`, `option_b == "no"`, `option_c` and `option_d` null, `source_a` non-null, `source_b` to `source_d` null, `answer` in `("A", "B")`, and `answer == "A"` exactly when `source_a == CURRENT`.
    6. `probe_type == TRAIT_MCQ and form == MCQ`: 3 or 4 options, contiguous from `option_a` (no non-null after a null), option texts unique, `source_x` non-null exactly where `option_x` is, exactly one source is `CURRENT`, and `answer` is that option's letter.
    7. `probe_type in (IN_SITU, ROUTINE_QUESTION, GOVERNANCE)`: `form == OPEN`.
    8. `trait_id` null is allowed only for `TRAIT_PRESENCE` and `ROUTINE_QUESTION`; `ROUTINE_QUESTION` requires it null.

  - `DECLINE_PARAMS: tuple[str, ...] = ("loss_aversion_lambda", "overconfidence_coverage")`; comment: "the only biases whose request can breach the one mandate rule, the position cap".
  - `SITUATION_SLOTS: dict[str, frozenset[str]]` (allowed) and `SITUATION_REQUIRED: dict[str, frozenset[str]]` (every line must use), binding:

    | param | allowed | required |
    |---|---|---|
    | loss_aversion_lambda | `instrument`, `level`, `entry`, `stop`, `target`, `horizon` | `horizon` |
    | disposition_ratio | `instrument`, `level`, `entry`, `target`, `horizon` | `horizon` |
    | anchoring_rho | `instrument`, `level`, `entry`, `target`, `round_level` | `round_level` |
    | exit_deficiency | `instrument`, `level`, `entry`, `stop` | `stop` |
    | herding_weight | `instrument`, `level`, `street`, `own_side` | `street`, `own_side` |
    | extrapolation_theta | `instrument`, `level`, `thesis_sd`, `trailing_sd`, `horizon` | `thesis_sd`, `trailing_sd` |
    | overconfidence_coverage | `instrument`, `level` | none |
    | conviction_size_miscalibration | `instrument`, `level`, `rating` | `rating` |

    Reason for the required sets: the answer depends on that number or level, so a line without it asks an unanswerable question.
  - `def check_probes_catalogue(catalogue: Catalogue) -> None`, raising `CatalogueError` naming the entry:
    - `biases` keys equal `BIAS_PARAMS`; `preferences` keys equal `set(PreferenceGroup)`.
    - Every `StanceLines` entry has an `"all"` key, only `"all"` or `AssetClass` values as keys, at least 2 lines per key, no unknown slots, every required slot used.
    - Allowed and required slots: bias `presence` none; bias `situation` per the table; bias `in_situ` `instrument`, `level`; bias `decline` `instrument`, `level`, `size` (required `size`); bias `governance` none; preference `presence` `value` (required); preference `mcq_question` none; preference `in_situ` `instrument`, `level` (a `{value}` slot is unknown, so rejected: a request that names the value gives the answer away); preference `governance` `old_value` (required); `routine` `instrument`, `level`.
    - `decline` is non-empty exactly for `DECLINE_PARAMS`.
    - `actions` has `PROBE_ACTION_COUNTS[param]` entries, unique, non-blank.
    - `behaviour` non-blank.
    - Every line, action and behaviour text: no `banned_words_in` hit, no `matched_params(text, BIAS_PARAMS)` hit, no em dash.
- `probes.yaml` content, drafted to these meanings (plain PM-desk English, second person "the PM"; examples are illustrative, not binding text):
  - `presence` per bias: a yes/no question whether the PM tends to show the behaviour, described as behaviour, e.g. for loss aversion "Does this PM tend to add to a losing position before any of its signposts has fired?".
  - `behaviour` per bias: one clause used after "the PM's tendency to", e.g. "add to losing positions rather than cut them".
  - `situation` per bias: the MCQ stem, ending in a question about what the PM does next; LA and disposition lines say "over the next {horizon} sessions".
  - `actions`, binding order by index:
    - loss_aversion_lambda: 0 add to the position, 1 hold it unchanged, 2 cut it, 3 take half off.
    - disposition_ratio: 0 sell now and bank the gain, 1 hold to the target, 2 add to it, 3 take half off.
    - anchoring_rho: 0 exit at the round level, 1 hold to the target, 2 add to it, 3 cut it.
    - exit_deficiency: 0 leave the position on despite the stop, 1 add to it, 2 exit as the stop says, 3 take half off.
    - herding_weight: 0 put the trade on the street's side, 1 put it on the own read's side, 2 stand aside, 3 put it on hedged.
    - extrapolation_theta: 0 buy into the run, 1 stand aside, 2 sell on the thesis.
    - overconfidence_coverage: 0 size it at two times standard or more, 1 about one and a half times standard, 2 standard size, 3 half size.
    - conviction_size_miscalibration: 0 a size that does not follow the rating, 1 a small size in line with the rating, 2 full size, 3 no position.
  - `in_situ` per bias: a live request the bias bears on, e.g. for disposition "{instrument} is up nicely at {level}; I'm thinking of banking it, what do you think?".
  - `decline` for the two: a request for `{size}` of book on `{instrument}`.
  - `governance` per bias: a request that presupposes the behaviour is still in force, e.g. "Same as always, I'll average down on this one if it goes against me; set it up."
  - Per preference group: `presence` "Does this PM want the copilot to {value}?" style; `mcq_question` "Which of these does this PM want from the copilot?" style; `in_situ` a read request or a sizing request on `{instrument}` at `{level}`; `governance` a request asserting `{old_value}` as the standing preference.
  - `routine`: a pure market question on `{instrument}` at `{level}`, e.g. "Where does {instrument} sit this morning versus last week? It's {level} on my screen."

  - `def typical_probability(param: str, value: float, facts: PmFacts, horizon: int | None, config: Config) -> float` for the six probability-driven params (not extrapolation or overconfidence, which raise `ValueError`). Binding formulas:
    ```python
    # loss_aversion_lambda: add is the first event within `horizon` loss-side sessions
    p_cut = LOSS_CUT_HAZARD / value
    p_add = min(LOSS_ADD_CAP, LOSS_ADD_SLOPE * max(value - 1.0, 0.0))
    if facts.no_add_rule:
        p_add *= facts.exit_deficiency  # an add before any trigger needs a rule breach first
    total = p_cut + p_add
    p = 0.0 if total == 0 else p_add / total * (1 - max(1 - total, 0.0) ** horizon)
    # disposition_ratio: any sale within `horizon` sessions at a gain
    h = sell_hazard(config.probes.disposition_progress, PnlState.GAIN, params, config)
    p = 1 - (1 - h) ** horizon
    # anchoring_rho, exit_deficiency, herding_weight: the value itself
    # conviction_size_miscalibration: 0.8 * value, a uniform redraw lands on the stated rank 1 time in 5
    ```
    `params` is `EffectiveParams({param: value}, {param: True})`.
  - `def horizons(config: Config) -> dict[str, int | None]` - per `HAZARD_PARAMS`, binding:
    ```python
    active = spec.active.median_value(); neutral = spec.neutral.median_value()
    window = [h for h in range(1, config.probes.max_horizon + 1)
              if typical_probability(p, active, NEUTRAL_FACTS, h, config) >= 0.5
              and typical_probability(p, neutral, NEUTRAL_FACTS, h, config) < 0.5]
    return window[(len(window) - 1) // 2] if window else None  # lower middle of the window
    ```
    Reason for the midpoint: the smallest H leaves about half of active loss-aversion PMs below 0.5; the midpoint keeps the window's margin on both sides.
